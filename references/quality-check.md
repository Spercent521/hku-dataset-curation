# 核对与验收

## 两个方向的实际检查

### 从输入检查输出

- 输入根目录及所有相关子目录均已盘点；压缩包、旧格式、隐藏幻灯片和读取失败有明确处置。
- 每个有效源文件、每张相关页面和图片都已检查，或被明确列为未完成；不是仅按文件名分类。
- 被排除为“空白”的 PPT 页，原始文字、图片关系和可见性已检查；有内容的源页因转换丢失时未被误记为无资料。
- 实际使用的转换结果与原始文字/表格交叉核对，中文、列头、比较符号和图片未消失；直接采用原素材不强制增加渲染流程。只检查页数和尺寸不能通过本项。
- 逐份核对有用材料的去向。病史、报告评价、表格、角度标注、图像和时间说明没有因提取方式而遗漏。
- 一个文件多个病例已拆分；同一病例多个来源已核对归属；没有因为目录结构凌乱就漏掉散落材料。
- 完全重复有出处记录；相似但有不同信息的材料未误删。

### 从输出反查输入

- 每个病例目录只有该病例可确认的材料；八个阶段名称准确，没有擅自增加或改写阶段。
- 输出根目录仅含病例目录和一份极简缺项 `README.md`；每例仅含八个阶段目录；没有其他整理报告、来源表、状态表、待确认区、原始 PPT、副本或缓存。原有医学检查报告是有效病例内容，不能误删。
- README 以“未提供的记录有：”开头，按“患者姓名 → 阶段 → 缺失记录”呈树状，只列已确认的缺项，不逐项重复“未提供”，不列已有资料或分析。缺项有已确认规范及实际来源检查支持，不从空目录直接推断；质量排除、未读或待确认项未被混写为缺失。
- 无 PPT 整页截图。逐图检查实际内容，不以规范文件名代替检查；MRI、CT、X线、参数和照片均已提取到可直接使用的内容区域。
- 混合页已按内容项产出；源中已有的病史、查体叙述、诊断/术式和并发症叙述有对应的规范文字，未仅藏在页面截图中。原有完整体检表或正式报告图像不强制重复转录。
- 可独立使用的参数表、影像、报告和大体照已经分离；完整的单一报告/对照图无须强拆。成品不要求读者重新拆解原 PPT。
- 每个输出图像及每个整理后的事实都能定位来源；样例数据未混入新病例。
- 已区分计划与实施、干预前后与手术前后、不同手术和随访时间点。
- 数值、单位、左右侧、节段、符号、小数和否定/不确定措辞已回看原文；未静默纠错、补算或补齐。
- 输出图像能打开、无关键内容截断，测量线和叠加标签仍在；多视角、拼图关系没有丢失。
- 不清晰的胶片或屏幕翻拍图已按质量标准排除，即使没有替代版本也未混入成品；排除基于原始图像而非预览或转换问题，原始输入未删除。此类排除已内部登记，不作为未完成项或额外报告交付。
- 图片阅读方向正确；成品名反映内容及已确认时点，不含“微信截图”“微信图片”“PPT页面”“复件”、相机编号或源页码；图内无聊天界面和无意义的来源文字，医学标注仍完整。
- 输出 RTF 格式真实且回读正确，中文和特殊符号未乱码；后缀与真实格式相符。
- 结果存放于独立位置，原始资料及样例未修改；无凭空创建的占位诊断或阴性结论。

## 内部核对

以下仅供独立临时工作区内核对，不生成交付报告或记录：

- 本次输入、输出、使用的样例及范围。
- 病例数、文件处理数量、读取失败和排除范围；统计忽略系统附属文件，不将其计为损坏临床资料。
- 每个病例的八阶段状态，允许“已整理；另有一项待确认”等组合状态。
- 局部缺失、不可辨认、未能读取和明确阴性分别表达。
- 冲突或疑问的具体来源、已做检查、保留方式和需要用户确认的问题。
- 最终检查的实际结果和剩余限制，不预填“全部通过”。
- 由逐项清单自动统计的文件数量及各类型数量，与实际输出一致；记录描述的阶段路径与实际位置一致。

内部阶段状态表的列仅服务于核对，不意味着病例正文必须具有相同字段：

## 验收判据

正常缺项不是错误：已完整检查而未提供某阶段资料，可以保留空目录并完成整理。不能为了“完整率”填补事实。

以下问题必须明确暴露，不能标为整批全部完成：输入未读完、病例归属仍冲突、有用资料无去向、输出无来源、关键图像/标注丢失、RTF 无法回读、关键数值尚未核对。可先交付确定部分，但说明受影响病例和内容范围。

**不得通过的归档替代品**：原始材料有文字诊疗内容却只交付图片；交付 PPT 整页截图；仅改名 MRI/CT 却未提取实际内容；中文在转换后消失；有用原图被误判空白排除；类型/阶段未确认却任意塞入确定阶段；内部来源记录仅有无法反查的分组通配符；交付目录夹带额外报告或过程材料。即使八个目录齐全、原始文件复制无误，也不能通过。

先用本批次的真实混合页或高风险材料做端到端小样，核实内容拆分、文字回读、局部图像、正确阶段和逐项来源，再推广。不要仅用规则文字匹配或预设问题清单替代实际产物检查。

核对复用已有逐项记录：确认全部素材有去向或排除理由，重点复查变换结果、异常项及未完成项。没有新问题时，不重新导出全批素材、重做全部 OCR 或再次渲染所有页面；复用不等于跳过尚未完成的检查。

## 行为自测场景

创建或修改本 skill 后，用下列场景检查决策是否符合规则；这是规则自测，不等于已经在真实原始数据上验证提取能力。

| 输入情况 | 应有行为 |
| --- | --- |
| 唯一一张胶片翻拍图明显模糊、反光，主体不能清晰辨认 | 排除出整理结果，原始输入保留；内部记质量不合格，不因没有替代版本放宽标准 |
| 翻拍图背景杂乱但影像主体和必要标注清晰 | 正常提取并检查内容，不仅凭拍摄方式或背景排除 |
| 有术前 X 线，未提供会诊、术前准备或并发症材料 | 保留空目录；记录范围内未提供，不生成“无需会诊”或“无并发症” |
| PPT 一页包含术前和术后参数，另有一张术前影像 | 保留两时点列及对照关系，参数表归术后复查；术前影像归影像诊断 |
| PPT 标明“牵引后、术前”，给出矫正率 | 归手术分期或干预，保留原给矫正率，不归术后，也不重新计算替换 |
| 文件名写术前，但页面明确为术后 | 按页面和可核实上下文分类，在来源记录说明文件名差异 |
| 一个目录里混入姓名、病例号不一致的报告 | 不盲目并入目录所属病例；暂存待确认并定位冲突 |
| 参数表写一个节段，对比页写另一个节段 | 回看后仍不同则保留两份原文及差异，不擅自统一 |
| 仅有原始 MRI，没有医生评价 | 保留 MRI，不生成正常/异常判断或医生评价文件 |
| 参数只有 `2.67`，没有单位 | 原样保留；记录原文未标单位，不从术前列补单位 |
| 表格有空格和 `-`，有一格模糊 | 空格、原符号和不可辨认分别保留，不统一写为阴性 |
| 某份旧 PPT 无法读取，其他资料已读完 | 列为未能读取，限定完成范围；不能声称相关阶段确定未提供 |
| 两张图很像，但其中一张带测量标注 | 视作不同有效材料；保留标注版本和有用原图，不按视觉相似去重 |
| PPT 内一张完整 MRI 原图，无独立叠加标注且归属清楚 | 导出原图并核对后直接归类，不额外渲染裁切该页 |
| 同一嵌入 X线图在两页重复，第二页另有角度标注 | 原图只提取一次，保留两页对象关系；只对需保留标注的页面做局部提取 |
| 续做时已有验证通过的素材和部分核对记录 | 复用已有结果，从待解决或未核对项继续，不重跑整批提取 |
| 新病例有样例未出现的明确会诊记录 | 归会诊，按实际内容命名；不因样例目录为空排除它 |
| 原始文字含中文病史，导出 PNG 只剩数字 | 判定转换保真失败；从原始文本恢复并核对，不以该 PNG 作为病史成品 |
| 渲染为白页，但原 PPTX 该页关联伤口照片或影像 | 检查实际对象、提取图片；不排除为无内容，未解决时报告转换异常 |
| 一页表格明确含“诊断”“手术”列 | 整理已有诊断和手术栏信息；实施状态不明则保留原文状态，不称未提供独立文本 |
| 一页 X 线、CT 和参数混排 | 提取对应图像及完整参数表，不只生成整页 PNG |
| 影像类型已知但日期未知 | 按已知类型规范命名，不在文件名添加未知日期；阶段未知在临时区继续核查，不交付待确认目录 |
| PPT 一页只有 MRI 拼图及页标题 | 提取完整 MRI 内容区域并保留必要标注，不交付整页截图 |
| 微信来源的一张 CT 图 | 提取 CT 内容及医学标注，命名 CT，不留聊天界面或“微信截图”等来源词 |
| 已完成内部来源表、核对表和整页渲染 | 交付病例八阶段成品和批次根目录极简缺项 README，核对后清理本次自建过程材料，不附其他报告 |
| 已查完相关来源，确无会诊记录 | README 的患者树下列“会诊 → 会诊记录”，不逐项写“未提供” |
| 只有低质量翻拍图且已排除，或旧 PPT 尚未读完 | 不把相关内容列入“未提供”的树；分别保留质量排除或未读状态 |
| 样例常见内容中包含 MRI 医生评价，本次并未确认其为核对项目 | 不机械地将医生评价列为缺项，不把所有常见内容转成必填清单 |
| 清单写 15 张术中照和 12 张体表照，实为 16 和 11 | 以逐文件清单纠正统计；不能因总数相同就声称核对通过 |

在使用者的实际环境和原始数据上检验跨格式读取、归属和提取是否可行；规则自测不能替代实际产物验证。只根据实际发现收紧规则，不把单个病例特例提升成所有病例的必填项。
