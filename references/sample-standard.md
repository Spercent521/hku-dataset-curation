# 样例与输出规范

## 规范依据与适用范围

本规范从已确认的整理要求与病例样例中抽象而来，仅保留目录、内容类型、命名和证据处理规则。公开分发包不包含真实病例样例、患者资料或本地处理记录。使用者提供自己的样例时，应实际读取并核对差异，不能把本规范当作已经检查本次材料的证明。

样例主要是脊柱病例。它们定义整理范式，不定义全部骨科疾病的必填项目。不得复制样例中的姓名、病例号、照片、数值和诊断到新病例；本 skill 不内置患者资料副本。

规范分三层：

| 层次 | 约束 |
| --- | --- |
| 固定骨架 | 一个可确认病例一个目录，每例仅含八个阶段目录；不交付额外记录 |
| 常见内容 | 有相应证据才输出，统一同义名称；数量和形式允许变化 |
| 开放内容 | 样例未覆盖但来源明确的材料仍保留，描述性命名，必要时待确认 |

## 输出布局

```text
<批次输出>/
  <病例目录>/
    病例评估/
    影像诊断/
    会诊/
    手术规划/
    术前准备/
    手术分期或干预/
    并发症/
    术后复查/
```

输出根目录只有病例目录，病例目录只有八阶段目录；空阶段保持为空。来源索引、核对表、待确认材料和转换文件只可存在于独立临时工作区，不能放入交付目录，也不生成独立审查报告。内部追溯不要求病例数据变成 SQL、固定字段 JSON 或电子表格。

病例目录使用已有且核实的标识；已有可靠目录名可沿用。新建时优先用已核实姓名和病例号，年龄、性别、疾病简称仅在确有证据且有必要时添加。缺什么就省略什么，不用猜测中文姓名、年龄或诊断来凑齐名称。无法核实姓名但能确认独立病例时可用 `病例-001`，在记录中说明这只是整理编号。避免覆盖同名目录。

## 八阶段分类

| 阶段 | 样例已有内容与推荐名称 | 分类边界 |
| --- | --- | --- |
| 病例评估 | `病史.rtf`、`体格检查.png`、`术前大体照.png` | 主诉、现病史、既往史、已有体检叙述和体检表、术前外观；信息可同时散落于正文和图片 |
| 影像诊断 | `术前X线.png`、`术前bending像.png`、`术前X线及bending像.png`、`X线参数.png`、`柔韧度参数.png`、`术前CT.png`、`术前CT三维重建.png`、`术前MRI.png`、`术前CT医生评价.rtf`、`术前MRI医生评价.rtf` | 图像、已给测量表和已有医生评价分别保留；不要求同时存在 |
| 会诊 | 按已有科室或内容命名，如 `会诊记录.rtf` | 四个样例均无实际文件，不能从样例推导必需科室、结论模板或会诊事实 |
| 手术规划 | `诊断及手术规划.rtf`、`术中图像.png` | 沿用样例将术中图片放在此处的约定；正文区分拟行方案与已实施记录，不能由术中图片补写术式 |
| 术前准备 | `心脏超声.png`、`肺功能.png`、`BMD.jpg`、`骨龄.jpg` | 保留已有报告；检查项目不固定，不要求每例都有 |
| 手术分期或干预 | `干预-牵引.rtf`、`干预结果.png`，多个事件分别命名 | 包括术前牵引、分期及相关结果；“干预后、手术前”不是“术后” |
| 并发症 | 原始材料明确记载的并发症及处理，按内容命名 | 四个样例均无实际文件；空目录不表示无并发症，术前合并疾病也不自动变成手术并发症 |
| 术后复查 | `术后X线.png`、`术后CT.png`、`术后X线参数.png`、`术前术后X线对比.png`、`术前术后参数对比.png`、`术后大体照.png`、`术后即刻大体照.png` | 图像与参数表区分；对比材料保留时间点和对应关系；没有随访间隔就不编造 |

表中名称是统一命名的首选，不是每例必须创建的文件。文件名中只有能确定的内容才可写入“术前”“术后”“三维重建”等标签；时间不明则用中性名称并记录疑问。

### 样例揭示的边界

- 有病例的“术前准备”全部为空；其他病例有心肺功能、骨密度或骨龄。不得按其他病例补齐。
- 原始参数页的标题、节段或单位可能与另一页不一致；例如干预对比材料和参数表可能使用不同的长度节段标签。保留各自原文并登记差异，不替作者改正。
- 同一病例的术后资料可以是单独参数表，也可以是术前术后对照表；不强制转换成同一种表，不将缺少的一列补为零。
- `术后X线对比` 与 `术后X-ray对比` 在样例中分别可能是影像拼图和参数表，必须看内容，不按近似文件名去重。
- 多张 MRI、分开的上下肢体检表、多视角照片均为有效材料；不能为“一项一文件”删减。

## 内容项拆分：从材料到成品

不要求原始材料先有名为“病史”“手术规划”的独立文件。PPT 表格、正文、图内文字、照片中的检查单同样是可用来源。缺少独立文档不等于缺少该项内容。

| 原始材料 | 必须完成的整理 | 不能作为成品的替代行为 |
| --- | --- | --- |
| 一页含身份、主诉、查体和术后伤口经过 | 按实际内容整理病史、体检与并发症 RTF；已实施的术式另标为历史手术记录，相关照片归对应项 | 整页命名“病例1-页01.png”后全部放病例评估 |
| 病例汇报表含姓名、性别、诊断、手术 | 按列头读取并输出已有身份、诊断和手术信息；术式是否计划/实施不明时保留“原文手术栏”，不提升为已完成事实 | 只保留汇报表截图，并称“未提供独立规划文本” |
| 一页含 X 线、CT 重建和参数表 | 分别提取带标注影像与完整参数表，图文对应可追溯 | 只有一个“术前影像及参数-页02.png”，仍需使用者自行拆解 |
| 单页本身就是完整的带标注术前术后对照图 | 保留完整对照，按内容命名并归术后复查；具体随访时间可未知 | 因为它出自 PPT 或日期未知而归影像诊断 |
| 数字文件名或微信图片 | 读取图内标签与内容，明确的 X 线/CT/MRI 分开命名；再独立判断时间关系 | 只加“原始影像-”前缀，所有类型和阶段都留待确认 |
| 拍摄横置的大体照或报告 | 将成品旋转到正常阅读方向，保留原始副本路径及变换记录；按视角/内容命名 | 原样横置复制，只保留相机编号作为名称 |

拆分不等于重测或补写。参数已经存在时单独保留参数表；只有影像标注时保留影像标注，不从中创造原本不存在的表格。诊断、病史和并发症已有叙述时整理叙述，不从外观推断它们。

整页核对副本如有必要，仅放独立临时工作区，完成后删除。任何 PPT 整页截图均不交付，包括单一内容页；应提取或裁切出实际内容，去除幻灯片页框、页码、装饰、无关标题和空白。完整对照图、参数表或报告的内部结构和医学信息保持完整，不能为去版式裁掉医学标注。

## 命名、图文和内容保持

- 同义命名统一：`X ray` / `Xray` / `X-ray` / `x线` 统一为 `X线`；`查体` 统一为 `体格检查`；明确的心超报告可命名为 `心脏超声`。这些是文件名归一，不授权改动源图文字。
- 多份同类资料优先用来源明确的日期、事件、视角区分；仍需序号时用 `-01`、`-02`，序号不暗示时间先后。
- 成品名称只表达内容、已知阶段和必要视角，例如 `MRI-01.jpg`、`CT三维重建.png`、`术后X线.png`。禁止出现“微信截图”“微信图片”“PPT页面”“复件”、相机编号和源页码等无意义来源词；这些仅供内部追溯，不作末尾后缀。未知日期不写入文件名，已确认的类型必须保留，阶段不明则先解决归类问题。
- 文本性整理默认输出真实 RTF，符合样例；已有图片保留原编码和对应扩展名，提取或裁切的无损图文用 PNG。不通过改后缀伪装格式，不把 JPEG 转 PNG 当成质量提升。不因用户要求“只要结果”而删除样例已有的病史、规划或医生评价内容。
- RTF 正文按已有内容组织短段落或列表，删除空项目和无意义排版；不新增无证据的小标题内容，不强制每份病史包含相同小节。
- 原图本身是表格、报告或拼图时，优先保留完整、清晰的图像；不要求把所有表格强制转成正文，也不默认重绘样例蓝色或红色表格。
- 对 PPT 页，提取嵌入图或带相关文字和标注的内容区域，作为对应内容成品。只有嵌入图却丢失叠加测量线、角度标签或时间点，不算完整提取。单一内容页同样须提取内容区域，不能整页导出后仅换成 MRI、CT 等名称。
- 微信来源图片按实际内容处理，去除聊天界面、发送者、聊天时间条等非病例信息；不在成品上添加“微信截图”等字样。图内检查日期、左右侧、节段、测量值和有意义的时间对照标签仍须保留。无法安全分离界面与内容时更换提取方法，不用遮盖或生成补绘破坏证据。
- 图表需转录时逐单元格核对并保留原图。不能读取的格子不补写；不能用平均值、常见值或同一病例其他时点数据代填。
- 不要求所有文本翻译成同一种语言。清晰且无歧义时可做中文组织，保留专业缩写、节段和原文对应；疑似错拼、歧义表达保留原文并待确认。
- 未给隐私处理要求时，不擅自删除必要的病例标识或破坏证据，也不扩散身份信息。保持已有遮挡，不恢复被遮挡内容；公开发布或对外共享前另行确认脱敏要求。

## 缺项与开放性

八阶段目录始终保留，但无内容的目录内不创建“无并发症”“检查正常”等占位文档。

内部核对区分以下状态，不为这些状态创建交付文件：

| 状态 | 含义 |
| --- | --- |
| 已整理 | 内容已读取、拆分到位、规范产出、归类并核对；不只是复制或渲染 |
| 已归档，待内容整理 | 文件已保留，但内容提取、分类或规范产出尚未完成 |
| 未提供 | 在已完成检查的输入范围内未找到相关资料；不代表临床上未发生 |
| 明确记载无/正常 | 来源明确陈述的阴性或正常结果，保留适用项目、时间和出处 |
| 存在但不可辨认 | 有材料但关键内容读不清，已记录具体位置 |
| 未能读取 | 格式、损坏或工具限制导致尚未检查 |
| 归属/时间/分类待确认 | 内容可读但关键对应关系不明 |

一个阶段可同时有“已整理”内容和局部待确认问题，不能为了单一状态掩盖未解决项。只有完成相关输入的搜索与读取后，才能将其标为“未提供”；存在未读材料时说明检查范围有限。
